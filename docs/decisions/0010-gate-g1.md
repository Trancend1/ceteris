## Kalibrasi probe kebocoran dan validasi estimator label noise

### Desain **[F]**

- **Korpus:** 31 dataset yang lolos saringan Phase 1 (14 biner, 17 multikelas). Semua diukur pada partisi latih D₀.
- **Label noise:** `LabelUniform` dengan ε ∈ {0; 0,1; 0,3}. Pada ε = 0, fitur bocor sama dengan label tercatat.
- **Fitur bocor sintetis:**
  - salinan numerik label bersih;
  - versi kategorikal: tiap label dipecah ke 10 kategori murni.
- **Konfigurasi pohon probe** (`max_depth`; `min_samples_leaf`): (2; 0,05), (4; 0,01), (6; 0,005).
- **False flag:** fitur asli dengan AUC tertinggi mencapai ambang. Pada ε > 0, ambang adaptif untuk false flag memakai ε̂ tanpa fitur bocor.
- **Kode:** `calibrate_leakage` di `ceteris/experiment.py`, seed `derive_seed("calibration", dataset_id)`. AUC probe dihitung oleh `single_feature_aucs`, yang memberi hasil sama dengan `single_feature_auc` (uji `test_br15_multi_config_auc_matches_single_calls`).
- **Waktu:** sekitar 34 menit dengan 4 proses.
- **Grid diperkecil** dari rencana awal (4 level ε, 9 konfigurasi). Run dengan grid awal tidak selesai dalam 108 menit.

**Opsi B'** tidak ada di ADR 0007; opsi ini muncul dari temuan 2 di bawah. Rumusnya: `τ = max(τ_min; min(0,99; m · AUC_bocor(ε̂, prior)))`.

- `AUC_bocor` adalah AUC teoretis salinan label bersih terhadap label dengan noise seragam ε̂.
- Kelas yang dihitung sama dengan BR-15: kelas positif untuk biner, semua kelas (macro one-vs-rest) untuk multikelas.
- Prior kelas diambil dari D₀.

### Temuan

1. **[F] Hiperparameter pohon hampir tidak memengaruhi deteksi.** Yang menentukan deteksi adalah ambang. Pohon yang lebih dangkal hanya sedikit menurunkan AUC fitur asli (Tabel 1).
2. **[F] Rumus ADR 0007 hanya tepat untuk biner seimbang.**
   - ADR 0007 menurunkan AUC = 1 − ε secara analitis. Hasil empiris pada biner yang hampir seimbang mendukungnya: kr-vs-kp 0,892 dan madelon 0,890 pada ε = 0,1.
   - Pada biner tidak seimbang, AUC fitur bocor turun lebih cepat. Contoh pada ε = 0,1: bank-marketing 0,763, wilt 0,656.
   - Pada multikelas, AUC turun lebih lambat. Contoh: 10 kelas, 0,94 pada ε = 0,1.
   - Rumus one-vs-rest dengan prior kelas cocok dengan hasil empiris di 31 dataset: selisih ≤ 0,016 untuk ε = 0,1 dan 0,3.
   - Karena itu Opsi B hanya mendeteksi sekitar separuh dataset pada ε = 0,1.
3. **[F] Ada batas yang tidak bisa dilewati ambang mana pun.** Pada biner yang sangat tidak seimbang dengan ε = 0,3, AUC fitur bocor tinggal 0,54–0,60 (ozone-level-8hr, wilt, bank-marketing). Nilai itu berada di rentang fitur asli, dengan median AUC fitur asli tertinggi 0,788.
4. **[F] Estimator label noise tepat di median, tetapi menaksir terlalu tinggi pada dataset sulit.**
   - Median ε̂ terhadap ε:

     | ε | Median ε̂ (Q1–Q3) |
     | --- | --- |
     | 0 | 0,016 (0,006–0,092) |
     | 0,1 | 0,105 (0,095–0,151) |
     | 0,3 | 0,292 (0,277–0,325) |

   - Pada data tanpa noise sintetis, 8/31 dataset punya ε̂ > 0,05. Contoh: first-order-theorem-proving 0,289, mfeat-morphological 0,270, GesturePhaseSegmentation 0,179, mfeat-zernike 0,174.
   - Penyebab yang paling mungkin: learner lemah di dataset ini, sehingga contoh yang sulit ikut dihitung sebagai label bermasalah. Penyebab ini belum diuji.
   - Bila ada fitur bocor, ε̂ menjadi 0,000, 0,096, dan 0,279 untuk ketiga level di atas.
   - Semua false flag ambang adaptif berasal dari taksiran berlebih ini:
     - mfeat-morphological, `att6`, AUC 0,891, ε̂ 0,270;
     - kc1, `total_Op`, AUC 0,788, ε̂ 0,092.
5. **[F] Kebocoran label tercatat selalu terdeteksi.** Fitur yang menyalin label tercatat (kasus ε = 0) terdeteksi 31/31 dengan ambang tetap.
6. **[K] Label noise hanya menyembunyikan kebocoran label sebenarnya.** Salinan label tercatat selalu ber-AUC 1 terhadap label itu sendiri, berapa pun noise-nya. Yang tersembunyi oleh label noise hanya fitur yang menyalin label *sebenarnya* (misalnya diturunkan dari hasil akhir yang benar).
7. **[F] Biaya profil per run.** `compute_profile` dengan learner acuan dan satu konfigurasi probe butuh 33,5 detik pada mfeat-pixel, 12,3 detik pada optdigits, dan 11,5 detik pada nomao. Angka ini menjadi masukan rencana E0.

### Usulan B4 dan alasannya

Usulan di bawah dipilih pemilik repo pada 12/11/2026 (Opsi A).

**Pohon probe:** `max_depth` 4 dan `min_samples_leaf` 0,01 (bawaan saat ini).

- Deteksinya setara dengan konfigurasi lain.
- Kapasitas 16 daun untuk kebocoran yang tidak monoton.
- False flag 0/31 dengan ambang tetap, dengan selisih minimal 0,08 dari ambang.

**Ambang:** Opsi A, tetap 0,99.

- **False flag:** Opsi A satu-satunya opsi tanpa false flag. Kriteria ADR 0007 untuk memilih Opsi B membutuhkan batas false flag yang disepakati, dan batas itu belum ada.
- **Hasil B' optimistis:** B' disetel pada model noise yang sama dengan uji (seragam), sehingga hasilnya cenderung terlalu baik. B' juga belum diuji pada noise class-conditional (K3c).
- **Bisa dievaluasi ulang:** `leakage_auc` dan `p_label_noise_rate` tersimpan di `corruption_run`, dan prior kelas bisa dihitung dari D₀. Aturan ambang lain bisa dievaluasi di E0 tanpa menghitung ulang profil. Bila aturan berubah, `profile_config_id` baru.
- **Keterbatasan yang dicatat pada BR-15:** dengan Opsi A, kebocoran label sebenarnya pada data dengan label noise ≥ 0,1 tidak terdeteksi.

**Bila Opsi B' dipilih:** pakai m = 0,95 dan `τ_min` 0,60.

- `business-rules.md` BR-15 dan ADR 0007 harus diubah.
- `dqprofile` perlu prior kelas dari sampel probe.
- Uji properti ADR 0007 berlaku dengan rumus baru.

## Bukti Phase 2

- **Uji:** 123 uji lulus, cakupan paket 97%; `ruff check`, `ruff format --check`, dan `mypy` strict bersih.
- **Uji wajib yang terpenuhi:**
  - isolasi profil: daftar parameter `compute_profile` tertutup, hanya satu DataFrame (BR-20, AC-2);
  - uji impor AC-3, kini juga mencakup `experiment`;
  - penolakan tanpa profil parsial (BR-10, BR-11, tanpa fitur);
  - determinisme profil dan run (AC-12).
- **Tinjauan kode oleh peran terpisah:** 8 temuan. Tujuh diperbaiki dengan uji regresi:
  - probe BR-15 kini one-vs-rest per kelas dengan kode kategori berbasis proporsi kelas;
  - cek ID BR-13 memakai tipe asal;
  - sebaran cadangan yang sama untuk profil dan corruption engine;
  - seed run lepas dari konfigurasi profil;
  - lipatan tetap untuk noise floor estimasi;
  - seed profil tetap;
  - uji diperketat.

  Temuan kedelapan dicatat sebagai keterbatasan (di bawah).

## Keterbatasan yang dibawa

- **Run yang gagal tidak acak.** Label noise class-conditional multikelas pada level 0,30 bisa membuat kelas kecil turun di bawah 20 baris, sehingga kontrak input menolak profil dan run gagal. Kegagalan tercatat di `run_log`; jumlahnya diukur di pilot E0.
- **Bias deteksi outlier.** Outlier sintetis dibuat dengan pagar IQR, dan profil juga memakai pagar IQR. Mitigasinya fitur Isolation Forest dan pelaporan per jenis korupsi (ADR 0009).
- **Estimator label noise menaksir terlalu tinggi pada dataset sulit** (temuan 4 kalibrasi). `label_noise_rate` adalah fitur masukan meta-model, bukan klaim, sehingga biasnya ikut dipelajari meta-model. Angka ini tidak boleh ditampilkan sebagai taksiran label noise yang sudah tervalidasi.
- **Biaya profil per run 11–34 detik pada dataset terberat.** Jumlah run E0 dan E1 perlu memperhitungkan biaya ini.
- **Noise floor belum punya statistik ringkas.** Statistik dan jumlah seed masih **[T]** sampai G2 (`business-rules.md` hal terbuka #1). Fungsi `measure_noise_floor` dan `estimate_noise_floor` mengembalikan AUC per seed dengan lipatan tetap.
- **Pertentangan dokumen diselesaikan, dikonfirmasi lewat persetujuan G1 (B6).** ADR 0005 dan 0009 menyebut seed probe "turunan BR-84", sedangkan BR-12 meminta "seed tetap" dan BR-16 meminta profil identik di jalur riset dan scan. Seed profil tetap memenuhi BR-12 dan BR-16; seed run (korupsi, learner) tetap mengikuti BR-84.
