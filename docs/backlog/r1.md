# Backlog R1 — Scan untuk tim

- **Status:** **[K]** disusun di Phase 6 per 14/11/2026 ([ADR 0016](../decisions/0016-paket-keputusan-pra-r1.md)).
- **Asal:** rekonstruksi. Draf Long-MVP tidak tersedia di repository ini **[F]**. User story ditulis ulang dari [product.md](../product.md) (feature index, persona, KPI), [architecture.md](../architecture.md) (API, AC, NFR), dan [business-rules.md](../business-rules.md), memakai ID `US x.y` yang sudah dirujuk feature index. Bila draf asli ditemukan, perbedaannya dicatat di bagian "Riwayat".
- **Kriteria keluar R1** (`product.md` 5): 5 ML engineer menjalankan scan pada data sendiri setelah epoch 1 ditutup ([ADR 0015](../decisions/0015-epoch-1-sejajar-sprint-c.md)); NFR-1, NFR-5, NFR-7, dan NFR-10 terpenuhi.

Setiap user story menyebut fitur (F-L..), phase pelaksana di [execution-plan.md](../execution-plan.md), dan acceptance criteria yang bisa diuji. Kriteria yang merujuk BR, AC, atau NFR diverifikasi dengan cara yang tercantum di dokumen sumbernya.

## US1.1 — Scan lewat API

**Sebagai** ML engineer (P1), **saya ingin** membuat scan dataset latih lewat REST API dari notebook atau skrip, **agar** estimasi dampak tersedia tanpa menjalankan paket di mesin saya sendiri.

- **Fitur:** F-L01 · **Phase:** 7
- **Acceptance criteria:**
  1. `POST /v1/datasets` mendaftarkan dataset beserta kolom target. `POST /v1/scans` membalas `202` dengan `scan_id` dan status `queued`.
  2. Berkas CSV atau Parquet di atas batas BR-10 ditolak dengan galat `{"error": {"code": "input_contract", ...}}` beserta alasannya, tanpa estimasi parsial (BR-10, BR-11).
  3. Data di luar rentang korpus (2.000–50.000 baris setelah kontrak input) tetap di-scan, dan `input_warnings` memuat `outside_corpus_range` (ADR 0016 K5). Peringatan ini ditambahkan di jalur scan, sehingga CLI dan API sama-sama memuatnya.
  4. `ScanReport` hasil API identik dengan hasil CLI dan Python API untuk data dan artefak yang sama (AC-5; uji konsistensi jalur SDK vs API).
  5. API, antrian, dan metadata store tidak menyimpan data mentah. Snapshot hanya di object store, dirujuk lewat `snapshot_uri` (AC-6).
  6. Endpoint sinkron memenuhi p95 ≤ 300 ms (NFR-2). Setiap scan punya trace dan log berkorelasi `scan_id` (NFR-9).
  7. Hanya endpoint `/v1` resmi; tidak ada alias draf awal (ADR 0016 K6).

## US1.2 — Unggah data lewat web

**Sebagai** ML engineer (P1), **saya ingin** mengunggah berkas data dan memilih kolom target lewat browser, **agar** saya bisa mencoba Ceteris tanpa menulis kode.

- **Fitur:** F-L02 · **Phase:** 9 (desain), 11 (implementasi), setelah G6
- **Acceptance criteria:**
  1. Unggahan menerima CSV atau Parquet sampai 500 MB per berkas. Berkas yang lebih besar ditolak di layar dengan alasan dan saran memakai SDK/CLI (ADR 0016 K5).
  2. Penolakan kontrak input ditampilkan beserta alasannya, bukan sebagai galat generik (BR-10, BR-11).
  3. Status scan (`queued`, `running`, `done`, `failed`) diperbarui sampai selesai, lalu laporan terbuka.
  4. UI tidak menghitung status sendiri; semua nilai berasal dari `ScanReport` (AGENTS.md butir 12).

## US1.3 — Laporan HTML

**Sebagai** ML engineer (P1), **saya ingin** membaca laporan scan sebagai halaman HTML yang bisa dibagikan, **agar** tim bisa memutuskan apakah data latih ini layak dipakai.

- **Fitur:** F-L02 · **Phase:** 11
- **Acceptance criteria:**
  1. `GET /v1/scans/{id}/report?format=html` dan halaman laporan web menampilkan ΔAUC, interval, status, temuan, dan peringatan input dari `ScanReport` yang sama dengan `format=json`.
  2. Setiap angka ΔAUC disertai kalimat kondisi (BR-06). Interval selalu tampil bersama flag OOD (BR-65).
  3. Label eksperimental tampil selama `model.experimental = true` (BR-35). Hanya klaim yang tercatat di register klaim yang tampil (BR-64): saat ini interval dan status berlabel eksperimental (KL-02, KL-04), dan klaim akurasi pada data nyata tidak tampil (KL-10).
  4. Temuan diurutkan menurut potensi pemulihan ideal, berlabel "potensi pemulihan ideal", tanpa total (BR-41–BR-43). Potensi ≤ 0 tampil tanpa angka (BR-45).
  5. Laporan menyertakan pertanyaan satu klik "apakah laporan ini mengubah keputusan Anda?" untuk KPI north star (`product.md` 6.2).
  6. Halaman tampil benar mulai lebar 390 px dan dapat dinavigasi dengan papan ketik.

## US1.4 — Scan asinkron dan status

**Sebagai** ML engineer (P1), **saya ingin** scan berjalan di latar dan bisa saya pantau, **agar** data besar tidak memblokir notebook atau CI saya.

- **Fitur:** F-L01 · **Phase:** 7
- **Acceptance criteria:**
  1. `GET /v1/scans/{id}` mengembalikan status, waktu mulai dan selesai, serta galat bila gagal, dalam bentuk `{"error": {...}}`.
  2. Worker membungkus `ceteris.scan` tanpa logika tambahan, hanya membaca registry (AC-4), dan tidak menulis ke data sumber (AC-7, BR-70).
  3. Scan median ≤ 5 menit untuk 100.000 baris × 100 kolom (NFR-1), diukur dengan uji beban.
  4. Scan yang sama pada data dan artefak yang sama memberi `ScanReport` identik, kecuali `scan_id` (AC-12).
  5. Klien SDK dapat menunggu sampai selesai (polling) tanpa mengubah bentuk hasil.

## US2.1 — Histori dan perbandingan antar-scan

**Sebagai** ML engineer (P1), **saya ingin** melihat histori scan sebuah dataset dan perbandingannya dengan scan sebelumnya, **agar** saya tahu apakah kualitas data latih membaik atau memburuk.

- **Fitur:** F-L03 · **Phase:** 8
- **Acceptance criteria:**
  1. `GET /v1/datasets/{id}/scans` mengembalikan daftar scan beserta versi model masing-masing.
  2. Scan lama tidak dihitung ulang otomatis saat artefak naik versi; laporan lama tetap menunjuk versi lamanya (BR-61).
  3. Perbandingan hanya dibuat antar-scan dengan versi model yang sama. Bila berbeda, profil lama yang tersimpan diestimasi ulang dengan model baru, dan perbedaan versi disebutkan (BR-62).
  4. Scan dihapus lewat *soft delete* (`deleted_at`); estimasi tetap tersimpan untuk audit (`architecture.md` 6.3).

## US2.2 — Versi model

**Sebagai** ML engineer (P1), **saya ingin** tahu versi artefak model mana yang dipakai setiap scan dan seberapa akurat versi itu, **agar** saya bisa menilai seberapa jauh estimasinya bisa dipercaya.

- **Fitur:** F-L04 · **Phase:** 7
- **Acceptance criteria:**
  1. Registry artefak menyimpan artefak beserta manifest dan metadata wajib (`architecture.md` 6.2). Artefak tanpa metadata wajib ditolak.
  2. Artefak baru hanya dirilis bila tidak lebih buruk dari laporan akurasi artefak sebelumnya pada set uji regresi (BR-63, NFR-8).
  3. Versi profil dan versi artefak yang tidak cocok menghasilkan galat eksplisit, bukan estimasi (BR-23, AC-9).
  4. Setiap `ScanReport` memuat `model.version` dan `model.profile_schema_version` (BR-60).
  5. Artefak `1.0.0` dipakai selama Phase 7–8. Penggantian ke artefak epoch 1 tidak mengubah kontrak API atau `ScanReport` (ADR 0015 butir 4).

## US8.1 — Login dan akses

**Sebagai** anggota tim yang memakai satu instans self-host, **saya ingin** masuk dengan akun sendiri dan memakai token API pribadi, **agar** hanya orang yang berhak yang bisa membuat dan membaca scan.

- **Fitur:** F-L05 · **Phase:** 8
- **Acceptance criteria:**
  1. Web UI memakai akun lokal (email dan kata sandi ter-hash dengan Argon2id atau setara). SDK/CLI memakai bearer token API per pengguna (ADR 0016 K4).
  2. Token bisa dibuat, dilihat sebagian, dan dicabut oleh pemiliknya. Token yang dicabut langsung ditolak.
  3. Semua endpoint `/v1` kecuali kesehatan layanan menolak permintaan tanpa kredensial yang sah.
  4. Kata sandi dan token tidak pernah tercatat di log atau trace (NFR-5, NFR-9).
  5. OIDC dan RBAC tidak dibangun di R1 (R2, F-L09).

## US8.3 — Paket self-host

**Sebagai** tim yang tidak boleh mengirim data keluar lingkungannya, **saya ingin** menjalankan Ceteris di infrastruktur sendiri dari satu paket, **agar** data mentah tetap di lingkungan kami (BR-71).

- **Fitur:** F-L05 · **Phase:** 8
- **Acceptance criteria:**
  1. Docker Compose menjalankan API, worker, Redis, Postgres, dan object store S3-compatible (SeaweedFS, ADR 0019) dari repository bersih dengan satu perintah dan dokumentasi singkat (syarat G5).
  2. Scan berjalan tanpa akses jaringan keluar (BR-71).
  3. TLS 1.2+ untuk lalu lintas di luar host, serta enkripsi at-rest untuk object store dan Postgres (NFR-5).
  4. Kontrak API dan `ScanReport` berversi; OpenAPI `/v1` dibekukan di G5 (NFR-10, AC-10).
  5. Pipeline CI menjalankan SAST serta pemindaian dependensi dan lisensi di setiap PR (NFR-6).
  6. Retensi hosted (NFR-7, BR-72) tidak berlaku karena R1 tidak membangun hosted (ADR 0016 K2). Dokumentasi self-host menjelaskan bahwa retensi data ada di tangan operator.
